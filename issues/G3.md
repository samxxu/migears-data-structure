# G3 — Skip guard: `tests/RedisTestCase.php` marks the integration half …

## Finding / 问题

- EN: Skip guard: `tests/RedisTestCase.php` marks the integration half skipped when no Redis server answers, and the workflow runs `vendor/bin/phpunit` with no `--fail-on-skipped`. A run in which those tests skip still exits 0, so the half can report green while running nothing — the failure mode `migears-cache`'s workflow names in a comment. Standard: put `--fail-on-skipped` on the CI command line rather than in `phpunit.xml.dist`, so a maintainer running the suite as root locally does not get spurious failures, or install the dependency so that nothing skips. This module held that guard until 2026-09-28: the previous `.github/workflows/ci.yml` ran `composer test:integration -- --fail-on-skipped`, commented "without the flag the whole integration half could be reported as passing while running nothing". The move to the shared `tests.yml` kept the Redis service but dropped the flag. The service makes the tests able to run; the flag is what makes a skip visible, and those are not the same guarantee.
- 中文: 跳过守卫：`tests/RedisTestCase.php` 在连不上 Redis 时会把整个 integration 半个套件标记为跳过，而工作流用的是不带 `--fail-on-skipped` 的 `vendor/bin/phpunit`。这些用例被跳过时整次运行仍然退出 0，也就是那半个套件可以在什么都没跑的情况下报绿——正是 `migears-cache` 工作流注释里点名的失效模式。标准做法是把 `--fail-on-skipped` 放在 CI 命令行上而不是 `phpunit.xml.dist` 里，这样本地以 root 跑套件的人不会看到假失败；或者把依赖装上，让没有用例会跳过。本模块直到 2026-09-28 都持有这道守卫：此前的 `.github/workflows/ci.yml` 执行 `composer test:integration -- --fail-on-skipped`，并注明「没有这个开关，整个 integration 半个套件可以在什么都没跑的情况下被判为通过」。迁移到共享 `tests.yml` 时保留了 Redis service，却丢掉了这个开关。service 让用例「能够」跑；开关才让「跳过」可见——两者不是同一个保证。
